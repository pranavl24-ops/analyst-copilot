# Analyst Co-pilot

A ticker goes in, a one-page investment-committee memo comes out. The tool pulls
financials, validates them, runs a valuation appropriate to the company's
industry, cross-checks against peers, and renders a PDF memo with a valuation
"football field" chart.

**All arithmetic happens in Python. The LLM only writes prose** — it receives
finished figures and is forbidden from inventing, estimating, or recomputing any
number. And the memo defaults to a free, deterministic offline renderer, so you
don't pay for the API unless you ask to.

```
python copilot.py CIPLA.NS                 # pharma -> FCFF DCF
python copilot.py ICICIBANK.NS --model bank  # bank  -> excess-return
```

Each run writes `out/<TICKER>/`: `memo.pdf`, `memo.md`, `payload.json`, and
`football_field.png`.

---

## What it does

For a given ticker the pipeline runs end to end:

1. **Fetch** — load financials and market data through the source cascade.
2. **Validate** — separate broken data (raises) from suspicious-but-usable data
   (surfaced as warnings the memo must address).
3. **Pick a model** — map the company's sector to the right valuation engine.
4. **Value** — project and discount, with a sensitivity grid around the answer.
5. **Comps & ratios** — a peer-multiple cross-check and the key operating ratios.
6. **Memo** — assemble every computed figure into one payload and render the memo.
7. **PDF** — draw the football-field chart and print a one-page PDF.

## How to run

Requires Python 3.11+.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Required one-time setup: download the headless browser used to print the PDF.
playwright install chromium
```

Then:

```bash
python copilot.py CIPLA.NS
python copilot.py ICICIBANK.NS --model bank
```

`--model` forces a specific engine (e.g. `bank`, `fcff`) and overrides the
sector map.

### Memo mode — offline by default, live on request

The memo is generated by `memo.generate_memo`, which reads `MEMO_MODE`:

- **`offline`** (default) — a deterministic template memo built entirely from the
  computed numbers. No network, no cost. This is what tests and demos use.
- **`live`** — calls the Claude API (`claude-sonnet-4-6`) to author the prose.
  Opt in explicitly so money is never spent by accident:

  ```bash
  export ANTHROPIC_API_KEY=sk-ant-...   # or put it in .env
  MEMO_MODE=live python copilot.py CIPLA.NS
  ```

Both modes produce the same seven sections — recommendation & target, business,
valuation, assumptions, sensitivity, risks, and a one-line close — and the live
prompt carries the same hard rule: the model writes prose only and may not touch
the numbers.

### Configuration

API keys come from environment variables (via a local `.env`, loaded with
python-dotenv). Never hardcode them.

- `ANTHROPIC_API_KEY` — only needed for `MEMO_MODE=live`.
- `FMP_API_KEY` — Financial Modeling Prep, for live statement fetches.

## Architecture

Valuation is a **strategy pattern**, not one model:

- `core/valuation/base.py` — the `ValuationModel` ABC and the `ValuationResult`
  protocol every result satisfies.
- `core/valuation/fcff.py` — `StandardFCFF`, a free-cash-flow-to-firm DCF for
  industrials, consumer, pharma, and IT.
- `core/valuation/financials.py` — `BankExcessReturn` for banks and NBFCs.
- `core/valuation/registry.py` — maps sector → model, with a manual override and
  an explicit refusal list.
- `profiles/*.yaml` — per-sector default assumptions and sanity thresholds.

`copilot.py` orchestrates the pipeline; `core/ratios.py` and `core/comps.py`
compute the ratios and peer cross-check; `memo/prompt.py` builds the payload and
the memo text; `memo/render.py` draws the chart and prints the PDF.

### Why banks use excess return at the cost of equity, not FCFF/WACC

For a bank or NBFC, **leverage is the product, not a financing choice**. Deposits
and borrowings are raw material, not capital structure, so the FCFF/WACC frame —
which treats debt as financing to be weighted against equity — is the wrong model
and produces meaningless numbers (free cash flow and a blended cost of capital
don't describe how a bank creates value).

So banks are valued by **excess return (residual income)**: the bank is worth its
**book equity** plus the present value of the returns it earns *above* its cost of
equity, and those excess returns are discounted at the **cost of equity (CAPM)** —
never the WACC. Concretely, each year's excess return is `(ROE − Ke) × book
equity`, discounted at `Ke`, with a terminal excess-return tail. The value is
expressed as an implied price-to-book. The tool refuses to let bank inputs flow
through the FCFF engine.

The two engines share nothing but the `ValuationResult` surface, so the rest of
the pipeline (memo, chart, comps) treats them uniformly while each speaks its own
language — the memo says "DCF / WACC / free cash flow" for an FCFF name and
"excess return / cost of equity / price-to-book" for a bank.

### Sectors the tool refuses

The registry deliberately refuses to value sectors a single-point DCF would
mislead on, printing why: **REITs and real estate** (valued on NAV/FFO),
**oil & gas and metals & mining** (commodity/cyclical), and **insurers** (need an
embedded-value/float model). Better to refuse than to emit a confident wrong
number.

## Data integrity

Financials are merged through a fixed **source cascade**, recorded per field:

```
override  >  FMP  >  yfinance (statements fallback)  >  flagged "missing"
```

- **The override is the trust anchor.** `data/overrides/<TICKER>.yaml` wins
  field by field over every API. For any name actually being pitched, the override
  is where audited, double-checked inputs live — and where the valuation
  assumptions (forecast, discount rate, peer multiples) are pinned, since the
  statements→inputs projection wiring is intentionally deferred.
- **yfinance is the fallback** for Indian (`.NS`/`.BO`) statements that FMP's plan
  doesn't cover; it is normalized to the FMP schema and treated as
  lower-confidence.
- **Nothing missing is ever zero-filled.** Fully-empty periods are dropped;
  genuinely-missing individual fields are surfaced as `MISSING` warnings that the
  memo must address honestly — never silently coerced to zero.

## Testing

```bash
pytest -q
```

The valuation-correctness tests must pass after any change to valuation code. No
test calls the live Claude API — memo tests run against the offline renderer.

## Limitations

This is a decision-support tool, not an oracle. Known constraints:

- **Terminal value can dominate.** In a DCF, most of the value often sits in the
  terminal tail; the engine flags when TV exceeds ~75% of enterprise value, but a
  high share means the answer leans heavily on long-run assumptions. Treat the
  sensitivity range, not the point estimate, as the result.
- **Indian fundamentals are patchy.** FMP's coverage of `.NS`/`.BO` names is
  incomplete, and the yfinance fallback has known label-mapping and
  year-alignment quirks. Validation surfaces these, but they are real.
- **Some sectors are deliberately unsupported.** REITs, commodities/cyclicals
  (oil & gas, metals & mining), and insurers are refused by design — a generic
  DCF is the wrong tool for them.
- **The bundled override figures are illustrative.** The numbers in
  `data/overrides/CIPLA.NS.yaml` and `data/overrides/ICICIBANK.NS.yaml` (and the
  peer multiples) are tuned demonstration inputs, not audited financials. **A real
  pitch requires audited inputs in the override** — it is the trust anchor, and it
  wins field by field.
- **The statements→inputs projection is not yet wired.** Valuation inputs come
  from the override's `valuation` block; a ticker without an override is refused.
